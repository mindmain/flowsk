# Flowsk Root Governance (`AGENTS.md`)

This project uses **Flowsk** (`flowsk`) to manage and coordinate work: always use Flowsk tasks when organizing and executing work. Before starting any request, inspect and organize the tasks in Flowsk first, and follow the `flowsk` operational skill and MCP instructions (`flowsk_digest`, `flowsk_search`, `flowsk_execute`, `flowsk_language_guide` — or run `flowsk status` / `flowsk install` if the skill is not yet loaded).

## 1. Scope & Stack Reference
Root operational governance for `module github.com/mindmain/flowsk` (`cmd/flowsk/main.go`, `web/`, `Dockerfile`, `docker-compose.yml`, `Taskfile.yml`, `README.md`, and subsystem boundaries). Refer to [STACK.md](./STACK.md) for the complete mapping of Go `1.26.0` packages, Angular `21.1` + Tailwind CSS `v4.1` + `@ngrx/signals` Web UI assets, protocols, adapters, and verification tools, and delegate subsystem specifics to `./{proto,db,internal}/AGENTS.md`.

## 2. Architecture, Usage & Style Invariants
- **Local-First `~/.flowsk` Home, Embedded Real-Time Web UI & Optional Network Dual Mode**: By default (`FLOWSK_SERVER_URL` empty), `flowsk` operates purely locally inside a single self-contained user folder `~/.flowsk/` (`$FLOWSK_HOME`, storing `~/.flowsk/flowsk.db`, `~/.flowsk/config.yaml`, `~/.flowsk/local_paths.json`, `~/.flowsk/snapshots/`, `~/.flowsk/projects/<workspace_id>/<project_id>.md`, and `~/.flowsk/tasks/<workspace_id>/<task_id>.md`) so all memory, tasks, Markdown docs, and goals survive even if the binary is removed. Running `flowsk ui` (alias `flowsk web`) or `flowsk serve --ui` serves the embedded Angular SPA (`//go:embed` in `internal/adapter/webui`) alongside Buf Connect (`ConnectRPC` over HTTP/1.1 & HTTP/2) and a tenant-isolated Go-channel real-time SSE stream (`GET /api/events` in `internal/transport/connectrpc`, relaying both in-process RPC mutations and cross-process CLI/`stdio` MCP SQLite WAL commits), and other workstations or containers can connect over the network via `--server-url` / `FLOWSK_SERVER_URL`.
- **First-Class Terminal UX, Lip Gloss TUI Installer, Minimalist Live Web UI, Structured Goals Roadmap, Multi-Project `flowsk status`, `flowsk init`, `flowsk doctor`, `flowsk update`, Orphan `prune` & Cloudflare Code Mode**: Every entity — workspaces, logical projects, non-destructive multi-binding sub-project hierarchies (`project_bindings` DAG, top-down & bottom-up auto-binding via `flowsk init`), grouped Git worktrees with per-checkout/subpath commits, strategic goals/objectives (`goal`, `milestone`, `cycle` with `planned`/`active`/`at_risk`/`achieved`/`dropped` statuses and live multi-state task completion progress), hierarchical tasks (including project-unique `external_id` for ClickUp/Linear/Jira/GitHub sync, `archived` state, and permanent workspace archive purge via `flowsk task purge-archived`), per-task/per-project `.md` docs (`flowsk task doc`, `flowsk project doc`, and atomic `DryRun`-safe `flowsk.{tasks,projects}.{getDoc,setDoc,deleteDoc}` / `markdown` attachments in `codemode`), orphan reconciliation (`flowsk prune` + yellow warning in `flowsk status`), embedded operational AI skill & MCP installer (`internal/skill` with SHA-256 verification, Lip Gloss + Bubble Tea 3-stage `flowsk install` installing both `SKILL.md` and `flowsk` stdio MCP with Universal defaults, `flowsk doctor`, and GitHub release check `flowsk update`), searches (`flowsk search`, `ext:<id>`, `is:md`, `--done`, `--in-progress`, `--blocked`), and boards (`flowsk board` / `flowsk status` and live SSE-streamed drag-and-drop Kanban/Grid, dedicated **Goals & Roadmap** view, live agent activity feed, hierarchical Project/Subproject selector & unbound-folder Projects Overview in `flowsk ui` / `flowsk web`) — renders cleanly across interactive terminals (`--format human`), low-token symbolic formats (`compact`, `tsv`, `jsonl`, `--max-tokens`), and **Cloudflare Code Mode** (`flowsk_search` + pure-Go `dop251/goja` ES6 JavaScript `flowsk_execute` / `flowsk code`).
- **Strict 3-Layer Isolation**: Upper transport protocols (`ConnectRPC` in `internal/transport/connectrpc`, `MCP` in `internal/transport/mcp`, `CLI` in `internal/cli`, and Angular SPA in `web/`) never contain business rules or SQL; core procedures (`internal/domain/*`, `internal/language`) remain pure with zero transport, driver, or filesystem imports; external dependencies (`SQLite`, `PostgreSQL`, `goja` Code Mode VM, `mdstore` Markdown file store, `webui` embedded SPA handler, shared volumes, local path store, formatters, RPC client) live exclusively in `internal/adapter/*`.
- **Zero Target-Repo & Server Path Footprint**: Never write Flowsk metadata files inside user repositories and never persist, transmit, or log host filesystem paths on the server or in Protobuf/SQL schemas; project-to-directory bindings exist solely on the client in `~/.flowsk/local_paths.json` (`internal/adapter/localpath`).
- **Multi-Tenant & Transactional Safety**: Enforce `workspace_id` ownership (`internal/domain/authctx`) and `deleted_at IS NULL` soft-delete guards on every read/write, and execute multi-step mutations plus `audit` records atomically via `internal/domain/tx`.
- **Direct Mandate — Comprehensive English Comments & Code**: Write all Go source code, Protobuf schemas, SQL migrations/queries, Dockerfiles, Taskfiles, and comments strictly in English. Every `.proto` file (package, `service`, `rpc`, `message`, `enum`, enum value, and `field`), every `.go` file (file/package header and every exported type, struct field, constant, interface, and function/method), and every `.sql` file MUST carry clear, explanatory English documentation comments. Never hand-edit `gen/go/**` or `internal/adapter/db/*/sqlcgen/**`.

## 3. Hierarchical `.prompts` Tree & MCP Lifecycle
- Untracked Italian architectural docs and operational plans reside in `.prompts` (ignored by `.gitignore`) at the minimum perimeter of work: single-subsystem work in `<subsystem>/.prompts`, cross-package internal work in `internal/.prompts`, and repository-wide plans in root `.prompts/`.
- Create, advance, and transition all plans, tasks, and checklist items exclusively via `ocin-ai` MCP tools; never manually delete `.md` files inside any `.prompts` directory.

## 4. Executive Orders & Verification Commands
1. **Ordine Esecutivo 1: Aggiorna sempre `AGENTS.md` e `STACK.md` ad ogni modifica rilevante di stack, architettura, adapter, comandi o struttura prima di concludere il task.**
2. **Ordine Esecutivo 2: Non cancellare mai file `.md` in `.prompts`; posiziona `.prompts` nel perimetro minimo del lavoro (servizio, dominio padre o root) e gestisci creazione, avanzamento e stato esclusivamente tramite i tool MCP di `ocin-ai`.**
3. **Direct English Commenting Mandate**: Comment every `.proto` service/RPC/message/enum/field, every `.go` file header and exported symbol, and every `.sql` schema/query thoroughly in English (`buf lint` `COMMENTS` profile enforced).
4. Keep `cmd/flowsk/main.go` strictly as the dependency-wiring and Cobra/server bootstrap entrypoint (`CGO_ENABLED=0` compatible).
5. Run full verification before concluding repository changes:
   ```sh
   task verify
   # Individual gates:
   task proto:lint && task sqlc:compile && task build && task test && task lint && task vuln
   ```
